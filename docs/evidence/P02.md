## What the checks prove

- Two fresh owned depots have convergent normalized SQLite tables/views/FKs/indexes and generated insert/select/update schemas for all eight safe APIs; each depot survives restart without schema drift.
- `profiles` is native-linked (`is_uuid`, no UUIDv7 default); `questions` has positive integer IDs, unique `source_id`, and source NULL/empty metadata fidelity. Real SQLite checks enable foreign keys and reject malformed/absent native profile IDs, cross-game composite FKs, duplicate memberships/team names/round order, invalid state phases, immutable host changes, invalid rate buckets, invalid audit actors/actions, and partial transaction writes.
- The circular assignment/private/history contract is measured rather than inferred: the host SQLite probe and a pinned authenticated WASM transaction probe both reject an incomplete partner transaction at commit and commit a complete atomic partner set. The test also exercises both mismatch-insert directions, rollback/no residue, valid-partner preservation, and the append-only/immutable update guards. TrailBase's private `Unsupported DEFERRABLE` log warning is retained as diagnostic context; observed pinned transaction behavior is the acceptance oracle.
- REST/list/count/filter/order/read, generated schemas, expand denial, direct mutation denial, excluded-column probes, private/unconfigured API denial, unrelated ordinary-account isolation and authorized filtered SSE setup/cancellation are exercised across the eight public projections. No private base Record APIs are configured.
- The fixture uses synthetic verified ordinary accounts and an anonymous display identity outside the UI. It does not import questions, grant browser admin capability or claim auth/mail, avatar byte validation, handler CAS/idempotency, live revocation/event delivery, gameplay, or native behavior.
