## Implementation

- `scripts/test-stack.mjs` creates a fresh marked `.local/test-runs/e2e-*` depot, random TrailBase/Mailpit ports, a fixed loopback Vite port with an occupancy refusal, explicit loopback/external-target guards, copied production migrations plus an isolated P04 config rendered from the checked-in development template and profile component, health + unique schema/auth readiness before and after reseed/restart, deterministic synthetic users/questions, and owned child teardown that bounds/escalates every child including Mailpit, attempts every stop/close step, preserves the first cleanup error for diagnosis/retry, and verifies owned PIDs and ports are gone before removing the depot.
- `tests/e2e/fixtures.ts` creates six independent contexts for H/A1/A2/B1/B2/X. Each ordinary actor signs in through the visible auth form; the display test gets its own context with no inherited storage. The auth test performs pre-login and post-login checks for distinct session identities/tokens and explicit per-context cookie/localStorage markers; the display test checks all auth storage classes. No saved auth state, forged token, API/SSE mock, shared game storage, or private corpus is used.
- The auth scenario registers a new account, reads the real verification message from the owned Mailpit API, opens the verification link in the browser, creates the profile through the app, requests a real reset message, submits the extracted token through the app reset form, logs in with the replacement password, and logs out.
- The harness scenario updates A1's profile through the app and awaits explicit `profile-sse-ready` barriers for H and X before mutation. X remains subscribed in its lobby tab while a second page in the same context performs the UI profile edit; H observes the authorized projection update plus ready-state, event-ID and event-count barriers through real `profiles_public` SSE without reload, while X receives its own pre-recorded event but neither H/A1 rows nor A1's event, readiness loss or count increment. X cannot read or patch H's private protected profile (both valid `/profiles/{id}` probes return TrailBase's documented 405 denial; the negative API probe reuses only X's real UI-issued authorization). The anonymous mutation probe remains covered separately by the backend matrix.
- `scripts/test-stack.test.mjs` covers foreign-owner cleanup refusal, production/external Mailpit URL refusal, multi-child sibling cleanup after one stop failure with retry, and an owned child/port disappearing after termination. `tests/e2e/diagnostics.spec.ts` is a no-op green check normally and an explicit failing assertion only when `E2E_FORCE_FAILURE=1` is supplied; it is never skipped.
- `.github/workflows/test.yml` installs locked dependencies and exact TrailBase/Mailpit/Chrome-for-Testing prerequisites, records the pinned Chrome version/revision/provenance, runs the induced failure and teardown check before the green Chromium suite, sanitizes both induced and green JSON reporter results, and uploads only those allowlisted metadata files, the bounded no-navigation diagnostic trace, and browser provenance. Raw Playwright results, backend/mail logs and gameplay traces remain private; stack teardown verifies owned PIDs and loopback ports are gone.
