# P04 evidence — real multi-user browser harness

## Scope and disposition

- Phase: `P04`, tasks `P04.T1`–`T3` implemented; criteria are evaluated below. Tested commit: `f32a01815e5cd1cb75e53fe63f56f5abbf481ecc`; exact committed gate output is `.artifacts/p04/p04-committed-final.log`. Parent phase acceptance remains a separate review checkpoint.
- The harness is synthetic-only. It never opens the P03 source database or private corpus, and all test accounts/passwords/mail data live in ignored, mode-0600 local run depots.
- Backend pin: TrailBase `v0.33.14-0-g3f965de7`, SQLite `3.53.2`; Mailpit `v1.31.0`; Playwright `1.63.0`; local browser channel `chrome` (installed Chrome 153.0.8010.37 in this environment).

## Implementation

- `scripts/test-stack.mjs` creates a fresh marked `.local/test-runs/e2e-*` depot, random TrailBase/Mailpit ports, a fixed loopback Vite port with an occupancy refusal, copied production migrations/config/profile component, health + unique schema readiness, deterministic synthetic users/questions, and owned child teardown.
- `tests/e2e/fixtures.ts` creates six independent contexts for H/A1/A2/B1/B2/X. Each ordinary actor signs in through the visible auth form; the display test gets its own context with no inherited storage. No saved auth state, token injection, API/SSE mock, shared game storage, or private corpus is used.
- The auth scenario registers a new account, reads the real verification message from the owned Mailpit API, opens the verification link in the browser, creates the profile through the app, requests a real reset message, submits the extracted token through the app reset form, logs in with the replacement password, and logs out.
- The harness scenario updates A1's profile through the app and observes H's authorized `/lobby` projection update through the real `profiles_public` SSE subscription without reload. X has a separate identity and cannot see H's protected profile; the unauthenticated mutation probe returns 401. The existing real-backend P02 authorization matrix remains the proof for authenticated cross-actor mutation denial.
- `scripts/test-stack.test.mjs` refuses foreign-owner cleanup and permits only the exact marker owner. `tests/e2e/diagnostics.spec.ts` is a no-op green check normally and an explicit failing assertion only when `E2E_FORCE_FAILURE=1` is supplied; it is never skipped.
- `.github/workflows/test.yml` installs locked dependencies and exact TrailBase/Mailpit/Chrome prerequisites, runs the induced failure and teardown check before the green Chromium suite, and uploads only JSON result metadata. Raw backend/mail logs and traces remain ignored/private.

## Residual limitations

- The browser CI lane currently covers Chromium/Chrome only. Firefox/WebKit, gameplay, display enrollment/pairing, disruption recovery, native display, and the private imported-question game remain later-phase work.
- The local Chrome binary is auto-updated rather than a repository artifact; CI provisions Chrome explicitly and records the installed channel. Video is opt-in because the local environment does not guarantee an ffmpeg installation; traces and failure screenshots are retained by default.
